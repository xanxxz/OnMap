## SDK и другие сетевые потоки

Уточнение по срокам MapTiler: его руководство указывает до 20 минут для IP на уровне Cloudflare CDN, тогда как Privacy Policy допускает хранение IP до 2 месяцев для ограниченных security checks. Это разные уровни/цели обработки; ни одно из этих заявлений не подтверждает, какой режим применён к аккаунту OnMap. См. [документацию MapTiler о personal data](https://docs.maptiler.com/guides/maps-apis/maps-platform/personal-data-in-maptiler-cloud/) и [Privacy Policy](https://www.maptiler.com/privacy-policy/).

- MapLibre RN 11.3.6 — renderer карты; явный сетевой поток — загрузка style/tiles. Прямых analytics/crash calls или передачи GPS в map request в коде не найдено. Удалённый style способен задавать tile hosts, поэтому нужен сетевой inventory release-сборки.
- В прямых mobile/backend dependencies и iOS Podfile.lock не найден отдельный analytics, crash-reporting или push provider SDK; в source search не найдено регистраций remote push и вызовов таких SDK. Это не исключает native/transitive поведения. Нужны Xcode privacy report release archive и финальная Android dependency inventory.
- Внешних font packages/remote font endpoints не найдено; используются системные шрифты. Это вывод по manifests/source, не анализ собранного binary.
- OpenFreeMap stylesheet использует OSM-данные, но в mobile runtime не обнаружен запрос к OSMF tile server; OSMF policy нельзя приписывать OpenFreeMap или независимым Overpass operators.
- First-party REST/Socket.IO — backend OnMap, не внешние SDK: bearer anonymous token, cityId/viewport; при создании события — выбранная координата, тип и поля события; feedback — ID события и действие; realtime — подписка на cityId. Production proxy/access logs и инфраструктурная retention не проверены.
- Физическая GPS позиция используется MapLibre location hook локально для маркера/камеры. Она отправляется первому backend только когда пользователь подтверждает создание события (как координата события); карта не получает её через GPS query. Выбранная координата может быть вручную исправлена.

## App Store Connect: что можно и чего пока нельзя утверждать

Apple считает collection передачу данных вне устройства, когда приложение или его partner может иметь доступ к ним дольше времени, нужного для обслуживания запроса в реальном времени; объявление охватывает также third-party partners. См. [Apple App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/) и [App Store Connect privacy workflow](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy). Обычный сетевой запрос сам по себе не доказывает tracking или collection; продолжительность доступа/логов важна.

По текущим потокам к уверенным собственным категориям-кандидатам для формы относятся:

- Precise Location — выбранные координаты события отправляются backend и связаны с anonymous identity; цель — App Functionality.
- User ID — подписанный anonymous identity token/UUID связан с событиями и feedback; цель — App Functionality.
- Other User Content — поля событий и Telegram sourceText/label обрабатываются и частично очищаются; цель — App Functionality. Sanitizer не удаляет все возможные личные сведения.
- Product Interaction — feedback о событии связан с identity и event; цель — App Functionality.

Это согласуется с текущим ios/RoadRadar/PrivacyInfo.xcprivacy (linked=true, tracking=false), но manifest и App Store Connect Privacy Details — разные проверки. Декларации manifest не доказывают полноту ASC.

Для provider-generated/retained IP, viewport, API request path и временных логов нельзя уверенно выбрать Apple data category/linked status только по публичной политике: нужно проверить конкретные account settings/contract и то, доступны ли логи дольше real-time request. Не отмечать tracking только из-за сетевого вызова, но и не заявлять no collection до проверки. Apple прямо требует учитывать third-party partner collection.

## Вопросы и проверки владельца

1. MapTiler: включён ли key в release, ограничения key, account privacy settings, tile hosts, регион/endpoint и логи.
2. TomTom: тариф/договор, opt-out request input/path/IP, регион, фактические traffic/search logs.
3. Yandex: проверить только Suggest/Geocoder ETL API-тарифы, договор, регион и API logs/retention. Weather удалён из продуктового runtime.
4. OpenFreeMap: активные tile hosts из style JSON и применимость опубликованной policy к ним/edge.
5. Overpass: точные операторы используемых instances, их privacy/retention либо замена на поставщика с известными условиями.
6. Backend hosting: регион, proxy/access logs, backups, срок хранения и доступы — отложено до настройки production hosting.
7. До отправки iOS/Android: Xcode privacy report archive, итоговый Android dependency inventory и hostname capture на release build.
