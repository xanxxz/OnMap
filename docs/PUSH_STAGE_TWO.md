# OnMap: push, этап 2

Шаблоны окружения оставляют отправку выключенной по умолчанию. На текущем VPS после резервной копии, пробного восстановления и применения миграции push-кампаний оба флага включены; это состояние конкретного сервера, а не значение по умолчанию проекта. APNs production для `com.onmap.app` настроен; адресный push на физический iPhone и открытие приложения по нажатию ранее подтвердил владелец. Массовую рекламную кампанию не запускали. Текущие правила кампаний и ДПС описаны в [PUSH_CAMPAIGNS_MVP_RU.md](PUSH_CAMPAIGNS_MVP_RU.md).

## Что работает в коде

- После разрешения уведомлений нативный модуль запрашивает APNs-токен на iOS или FCM-токен на Android; mobile регистрирует или обновляет его через анонимно аутентифицированный `POST /api/push/devices`. При отказе, сбросе identity или смене токена прежнее устройство отзывается/заменяется. Если Firebase-конфигурация Android отсутствует, токен не запрашивается и устройство не регистрируется. Исходный identity ID не пишется в таблицу устройств: хранится отдельный HMAC-ключ. Токен доставки хранится в БД, но не выводится в публичный API и логи.
- Отдельный durable outbox получает одно задание на устройство и метку. После этапа кампаний автоматический дорожный push допускается только для подтверждённого `ROAD_PATROL`; остальные типы не ставятся в очередь. Правила доверия, независимых подтверждений и ограничения частоты приведены в документе кампаний.
- Владелец создаёт информационную кампанию через `/push_new` или кампанию точки через `/partner_push <UUID>` в существующем moderation poller. Подтверждение запуска обязательно; создание/редактирование точки ничего не рассылает. Для одной точки действует ограничение раз в 24 часа на устройство.
- Worker проверяет актуальность цели перед отправкой, ограничивает отправку устройству, повторяет временные ошибки, отключает недействительный токен. Рекламное задание, пролежавшее в очереди больше 15 минут, отменяется, а не уходит неожиданно после позднего включения доставки. APNs/FCM отправка активируется только при `PUSH_DELIVERY_ENABLED=true` и подходящих файлах credentials. Тестовый `RecordingPushProvider` не подключён к production.
- Нажатие на iOS- или Android-уведомление о событии/точке (или URL `onmap://open/...`) открывает активную метку через адресный GET; отсутствующая/истёкшая метка даёт понятное сообщение. Информационная кампания открывает карту без карточки. Карточка партнёрской точки получает `promoCode` из публичного API. Холодный и тёплый запуск проверены на уровне JS-тестов; реальный tap адресного iOS push подтвердил владелец, а новые категории кампаний и переключатели требуют проверки в следующей мобильной сборке.

## Что обязательно сделать перед реальной рассылкой

1. Перед запуском доставки в новой инсталляции проверить миграции `20261012150000_add_push_devices_outbox` и `20261013130000_push_campaigns_preferences`. На текущем VPS обе применены.
2. В Apple Developer включить Push Notifications для реального Bundle ID и подписать сборку подходящим provisioning profile. Entitlements для Debug (`development`) и Release (`production`) добавлены в проект, но без соответствующего App ID/подписи APNs-токен не подтверждён. Проверить его получение и tap на физическом iPhone.
3. Для Android зарегистрировать в Firebase Release app `com.onmap.app` и сохранить его `google-services.json` в `android/app/src/release/` (файл игнорируется Git). Debug `com.onmap.app.dev` пока намеренно работает без Firebase: Gradle пропускает только `processDebugGoogleServices`, нативный модуль не регистрирует FCM-токен без FirebaseApp. Если позже понадобится FCM в Debug, зарегистрировать отдельное Android app `com.onmap.app.dev` и положить его JSON в `android/app/src/debug/`. FCM SDK, получение/обновление токена и обработка tap подключены, но без тестового устройства их работа не подтверждена. Автоматическая инициализация FCM выключена до разрешения пользователя.
4. Для новой инсталляции передать backend key-файл APNs и/или service-account JSON FCM через защищённый read-only mount вне Git. Настроить `APNS_TEAM_ID`, `APNS_KEY_ID`, `APNS_BUNDLE_ID`, `APNS_ENVIRONMENT`, `APNS_PRIVATE_KEY_FILE` и/или `FCM_SERVICE_ACCOUNT_FILE`; затем отдельно включить `PUSH_ENQUEUE_ENABLED` и `PUSH_DELIVERY_ENABLED`. Ключи не класть в мобильную сборку. На текущем VPS credentials уже подключены.
5. Проверить реальные sandbox/production endpoints, invalid-token response, восстановление worker после рестарта и исключить повторную доставку при сбое между провайдером и фиксацией `SENT`. Outbox обеспечивает идемпотентную постановку, но внешняя доставка остаётся at-least-once; APNs/FCM collapse key уменьшает вероятность дубликата, не даёт строгой гарантии.

Автоматические тесты используют mock/recording провайдер. Во время локальной проверки и деплоя кампаний реальные уведомления не отправлялись. Ошибки провайдера не логируются целиком, чтобы не вывести токены или закрытые URL.
