## Описание

OnMap — карта дорожных событий, которыми делятся пользователи.

Смотрите отметки на карте, сообщайте о дорожной ситуации в выбранной точке и помогайте другим пользователям оценивать её актуальность.

В приложении доступны события нескольких типов: ДТП, заторы, перекрытия, дорожные работы, опасности, дорожная обстановка и отметки ДПС. Часть данных может поступать из подключённых внешних источников, если они доступны.

Место события может быть выбрано вручную или определено приблизительно. Проверяйте положение и контекст по карте: отметки создаются пользователями или поступают из внешних источников и не гарантируют точность, полноту или актуальность.

OnMap не строит маршруты и не гарантирует объезд препятствий или контрольных постов. Отметки ДПС являются одним из типов дорожных событий на общей карте.

## Короткие App Review Notes

OnMap — карта дорожных событий с пользовательскими отметками и данными подключённых дорожных источников. Типы включают ДТП, заторы, перекрытия, дорожные работы, опасности и отметки ДПС. Приложение не строит маршруты и не предназначено для обхода правоохранительных органов.

Входа по аккаунту нет: приложение создаёт анонимный идентификатор для создания события и feedback. Разрешение геолокации не обязательно для просмотра карты; при отказе точку события можно указать вручную. Для проверки создания нужен доступный backend и рабочая конфигурация **[НУЖНО УКАЗАТЬ: production/test API endpoint перед отправкой]**.

В карточке события можно отметить актуальность и открыть действие «Пожаловаться». Оно формирует текст обращения и открывает Telegram; сообщение пользователь отправляет вручную. Встроенной административной очереди жалоб в приложении нет, поэтому не следует представлять переход как автоматическую регистрацию или обработку.

Для обращений используется Telegram `@onMapSupport`; обычные обращения оператор рассматривает не позднее трёх рабочих дней. Жалоба из карточки открывает подготовленный черновик, который пользователь отправляет сам. Это не автоматическая регистрация: защищённой очереди жалоб и встроенной панели модерации нет.

## Скриншоты: план съёмки

Сделать реальные скриншоты из release-сборки с работающим production/test backend, актуальной картой и без личных данных. Не использовать макеты, подчёркивающие возможности, которых нет.

1. **Основная карта:** несколько актуальных событий и видимый заголовок города.
2. **Типы событий:** фильтры, включая ДПС, без формулировки про обход полиции.
3. **Создание отметки:** выбор типа и ручная проверка точки на карте.
4. **Карточка события:** источник, примерное место (если применимо), доверие и срок, пришедшие от backend.
5. **Обратная связь:** действия «Актуально?» / «Уже не актуально».
6. **Жалоба:** показать выбор причины и честную подсказку о ручной отправке в Telegram.

Для проверки макетов снять экран на физическом **iPhone 16 Pro** (уже использовался владельцем для проверки) и на одном поддерживаемом **iPad**, если приложение будет распространяться как универсальное. В Xcode target указаны iPhone/iPad (`TARGETED_DEVICE_FAMILY = 1,2`). Перед загрузкой проверить актуальные размеры и обязательные слоты непосредственно в App Store Connect. Не включать тестовые телефоны, имена, сообщения Telegram или координаты частных лиц.
