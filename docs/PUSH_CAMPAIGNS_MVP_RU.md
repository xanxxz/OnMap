# Push-кампании OnMap — MVP

Система использует единственный существующий Telegram moderation poller и allowlist `TELEGRAM_PARTNER_OWNER_IDS`. Другой Telegram poller не создаётся. Секреты APNs/FCM остаются только на backend. Команды рассылок работают только от owner ID в личном чате.

## Настройки

- В шаблоне окружения `PUSH_ENQUEUE_ENABLED=false` и `PUSH_DELIVERY_ENABLED=false`. На текущем VPS после проверенного backup/restore и миграции оба флага включены. Включение не означает, что владелец уже запустил рекламную кампанию.
- `PUSH_ROAD_EVENT_NOT_BEFORE` — обязательная граница активации дорожных push в ISO 8601 UTC. События, созданные раньше этой даты, никогда не попадут в дорожную push-очередь, даже если их подтвердят позже. Без валидного значения дорожные push не создаются.
- `TELEGRAM_PARTNER_OWNER_IDS` — существующий allowlist владельца; модераторский chat ID сам по себе не даёт право управлять кампаниями.
- Уже зарегистрированные устройства после миграции получают включённые категории ДПС и новостей/предложений. Новое приложение показывает обе настройки под колокольчиком и позволяет независимо выключить каждую. Это решение владельца для MVP; системное разрешение iOS/Android остаётся отдельным.

## Команды владельца

`/push_new` создаёт информационную рассылку без привязки; `/partner_push <UUID>` — рассылку партнёрской точки. Мастер запрашивает города (для точки берётся её город), заголовок, текст и расписание, показывает аудиторию и предпросмотр. Только кнопка «Подтвердить запуск» создаёт кампанию. Черновик хранится в БД, а update ID и nonce/revision защищают от повторной доставки и старой кнопки.

`/push_list`, `/push_show <UUID>`, `/push_edit <UUID>`, `/push_pause <UUID>`, `/push_resume <UUID>`, `/push_cancel <UUID>`, `/push_status`, `/push_abort` управляют кампаниями. `/queue` и существующие moderation-кнопки не меняются.

Локально подготовленный новый мастер выбирает даты и время inline-кнопками; прежний строковый формат пока принимается для совместимости. У каждого поддерживаемого города должен быть явно задан IANA-часовой пояс. При выборе нескольких городов создаётся отдельное расписание на одинаковое местное время каждого города; пока в реестре поддержан только Балаково (`Europe/Saratov`). Повтор ограничен 90 днями и требует даты окончания. Новости и реклама доступны с 08:00 до 21:59. После простоя повторяющиеся пропущенные отправки не догоняются; разовая отправка допускает опоздание не более 15 минут. Аудитория выбирается заново при каждом запуске. «Принято APNs/FCM» не означает, что уведомление было показано на устройстве. Новая миграция городских расписаний ещё не применялась к рабочей БД/VPS.

## Дорожные push

Только `ROAD_PATROL`, статус `ACTIVE`, серверное доверие не ниже 70%, минимум два принятых подтверждения от разных identity приложения, кроме автора, и не менее 10 минут до истечения. Telegram-дубли и parser score не считаются независимыми подтверждениями: надёжного sender ID для этого нет. Проверка выполняется после создания и после принятого подтверждения, а также повторно перед доставкой. Дедупликация по событию и устройству. Текст не включает raw Telegram sourceText или произвольное имя: безопасная улица используется только при строгом совпадении шаблона, иначе показывается городская подпись без точного места.

Шаблоны: заголовок `OnMap · ДПС`; точная улица — `Есть подтверждённая отметка на ул. {улица}. Проверьте место на карте.`; приблизительная — `Примерное место: ул. {улица}. Проверьте точку на карте.`; без безопасной улицы — `В городе есть подтверждённая отметка. Откройте карту.` Информационная кампания открывает карту без карточки; партнёрская — её точку и карточку, если точка ещё доступна.

Ограничения на устройство: максимум 2 ДПС за скользящий час; новости и реклама вместе — максимум 1 за календарный день Саратова; одна партнёрская точка — не чаще раза за 24 часа; между любыми push не меньше минуты. Отложенные рекламные уведомления старше 15 минут отменяются. Вся очередь durable, ключ запуска повторяющейся кампании уникален, устройство проверяется перед отправкой.

## Включение и откат

Для текущего VPS выполнено: backup PostgreSQL и проверка restore во временную БД, проверка пустой старой очереди, установка `PUSH_ROAD_EVENT_NOT_BEFORE` на момент запуска, применение миграции `20261013130000_push_campaigns_preferences`, проверка единственного backend и Telegram locks. После этого оба флага включены; health, REST и Socket.IO проверены. При проблеме выключить оба флага и пересоздать только backend, не откатывая миграцию или данные. Старые зарегистрированные устройства и Telegram cursor сохраняются.

Новый iOS/Android build необходим для пользовательских переключателей категорий. Серверная часть может быть развёрнута до сборки, но владельцу не следует подтверждать рекламную кампанию до обновления клиента и проверки настроек на физическом устройстве.
