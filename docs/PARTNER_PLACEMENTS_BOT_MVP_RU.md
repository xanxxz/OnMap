# Партнёрские размещения: backend + Telegram-мастер (черновик эксплуатации)

Это отдельные сущности `partner_points`, `partner_point_contacts`, `partner_city_banners`; они не являются дорожными событиями. Публичный API остаётся только на чтение. Мобильное приложение показывает партнёрские маркеры, карточку и необязательный баннер.

## Доступ и запуск

- Используется существующий moderation bot и его **единственный** long-polling poller. Второй bot token, poller или webhook не создаются.
- `TELEGRAM_PARTNER_OWNER_IDS` — список числовых Telegram user ID через запятую. Пустое значение отключает партнёрские команды. Принимаются только сообщения и callback от этих ID **в собственном личном чате** с ботом. `TELEGRAM_MODERATION_CHAT_ID` остаётся отдельной настройкой очереди жалоб; мобильная anonymous identity для управления размещениями не используется.
- Перед развёртыванием партнёрские миграции, включая `20261009140000_add_partner_appearance`, нужно проверить и применить штатной процедурой на целевой БД. В рамках реализации они сохранены только в репозитории и **не применены на VPS**. Не меняйте production env до отдельного плана выката.

## Команды владельца

- `/partner_new balakovo` — создать черновик точки; мастер спрашивает название, категорию, описание, геопозицию Telegram или «широта, долгота», адрес, повторяемые контакты, даты, цвета, необязательные изображение и промокод, затем показывает предпросмотр. `/skip` пропускает необязательные поля.
- `/partner_edit <UUID>` — пройти те же поля заново; `/keep` сохраняет текущее значение. Старые контакты сохраняются, новые добавляются через кнопку. `/clear_contacts` удаляет контакты из **черновика**; сама точка меняется только после подтверждения.
- `/partner_status` — напомнить текущий шаг после перезапуска; `/partner_cancel` — отменить черновик.
- `/partner_list balakovo`, `/partner_pause <UUID>`, `/partner_resume <UUID>`, `/partner_end <UUID>` — ручное управление точкой. Завершённую точку нельзя возобновить; паузу можно снять только до конца размещения.
- `/partner_banner balakovo` — отдельный мастер заголовка, текста, HTTPS-кнопки, UUID связанной точки и срока. Он не меняет срок или статус точки. Баннер включается только после отдельного нажатия «Включить баннер»; `/partner_banner_off balakovo` выключает его.
- `/partner_price point|banner <UUID> <рубли>` и `/partner_paid point|banner <UUID>` — внутренние ручные отметки согласованной цены и оплаты. Оплата отмечается один раз, после указания цены; платёжного провайдера нет. Эти поля не входят в публичный API.

Время вводится ISO-строкой с часовым поясом, например `2026-10-10T12:00+04:00`. Для подтверждения баннера связанная точка должна иметь статус `ACTIVE`. Даты и статус баннера не активируют и не продлевают связанную точку. Публичная выдача скрывает баннер, если связанная точка уже не активна или вышла из срока.

В мастере точки после дат выбираются фон и цвет текста: готовыми кнопками или вручную в формате `#RRGGBB`. Бот принимает только пару с контрастом не ниже 4.5:1; при редактировании `/keep` оставляет текущий цвет. Цвета хранятся у точки. Баннер автоматически наследует их у связанной точки и после редактирования точки обновляется вместе с карточкой — отдельной пары цветов у баннера нет. Для старых точек миграция сохраняет прежний лесной фон `#153D32` и светлый текст `#FDFBF4`. В мобильной карточке выбранная пара используется на категории и основной кнопке связи; остальной текст остаётся нейтральным для читаемости.

После цветов владелец в личном чате может отправить PNG/JPEG/WebP как фото или документ размером до 4 МБ. Формат определяется по содержимому; повреждённые файлы и SVG отклоняются. Сервер декодирует файл и сохраняет только нормализованный PNG 256×256 с прозрачными безопасными полями. `/skip` оставляет прежнее изображение при редактировании либо использует штатную иконку, если изображения нет. Замена публикуется только при подтверждении точки; ошибка загрузки не удаляет прежний asset. Незавершённые загрузки удаляются при отмене/замене черновика. Изображения хранятся отдельно от дорожных событий в PostgreSQL и входят в backup БД. Публичный маршрут отдаёт PNG только пока связанная точка активна и находится в сроке размещения. При сетевой ошибке mobile показывает штатную иконку OnMap.

После изображения мастер спрашивает промокод. Допустимы 3–32 буквы или цифры (включая кириллицу), дефис и подчёркивание, без пробелов; регистр сохраняется. При создании `/skip` оставляет поле пустым, при редактировании `/skip` или `/keep` сохраняют прежний код, а `/clear_promo` удаляет его из черновика. Изменение/очистка появляется в публичной карточке только после подтверждения владельцем. Для неактивных точек промокод не выдаётся.

Черновик хранится в `partner_bot_drafts`. Обработка входящего Telegram update, изменение размещения/черновика и отметка update выполняются в одной DB-транзакции. Повтор update и устаревшая inline-кнопка не повторяют действие. Ответ Telegram отправляется **после** коммита: при сбое доставки действие сохранится, но подсказка может не прийти; `/partner_status` восстанавливает текущий шаг. Это ограничение следует проверить в ручном smoke после отдельного выката.

## Изолированная DB-проверка

`backend/test/jest-partner-integration.json` запускает отдельный интеграционный тест с настоящей PostGIS-БД, но с подменённым Telegram transport. Тест намеренно не входит в обычный `npm test`: для него нужны `NODE_OPTIONS=--experimental-vm-modules`, `PARTNER_INTEGRATION_DISPOSABLE=1` и `PARTNER_INTEGRATION_DATABASE_URL` к **одноразовой** БД на `127.0.0.1` с именем `onmap_it...`. Команда: `npx jest --config test/jest-partner-integration.json --runInBand`. Перед запуском примените миграции к этой БД; после проверки удалите только созданные для неё контейнер/том. Не направляйте эту команду на рабочую dev- или production-БД.
