# Партнёрская статистика — MVP

Статистика доступна владельцу в существующем Telegram-боте через `/partner_stats <UUID точки>`. Команда работает только для Telegram ID из `TELEGRAM_PARTNER_OWNER_IDS` в личном чате; отдельного poller-а и публичного API чтения нет. Ответ содержит агрегаты за текущий и предыдущие 6 дней, за текущий и предыдущие 29 дней и за всё время (дни — UTC). Финансовые поля и данные отправителей в ответ не входят.

События статистики: открытие карточки точки, нажатие конкретного контакта, показ баннера и нажатие кнопки баннера. Показ баннера регистрируется после 1 секунды непрерывной видимости: блок должен быть размещён на экране, приложение активно, карта в фокусе, а перекрывающие карточки/формы и выбор города закрыты. Перерисовка не создаёт новый показ. Нажатие считается действием даже если ОС не смогла открыть ссылку.

Сервер ведёт отдельные дневные счётчики `partner_stat_daily`. Для ограничения повторов он хранит только HMAC-псевдоним анонимного ID в `partner_stat_windows`, не токен; псевдоним различается для разных точек и действий. Минимальные интервалы между принятыми действиями одного клиента для одного размещения: карточка — 15 минут, контакт — 1 минута, баннер — 1 час для показа и 1 минута для нажатия. Просроченные псевдонимы удаляются при следующем принятом действии; отдельного гарантированного задания очистки пока нет. Координаты пользователя, значения контактов и сырые identity-токены в таблицы статистики не записываются. Контакт определяется UUID: смена подписи или порядка сохраняет UUID, а смена типа или значения создаёт новый. Исторические клики по удалённому UUID видны только как «Удалённый контакт N», без прежней подписи, номера или ссылки.

Новая общая метрика «анонимные идентификаторы с [даты начала учёта]» считает только identities, впервые замеченные backend после включения этой версии. Старые установки учитываются при первом новом обращении. В БД хранится отдельный keyed HMAC-хеш для дедупликации и счётчик; исходные токены и IP для этой метрики не сохраняются. Дата в отчёте — момент первой учтённой identity, историческое число пользователей или людей не оценивается. Смена серверного ключа HMAC нарушит дедупликацию старых identities, поэтому при ротации ключа нужен отдельный план миграции метрики.

Клиентская статистика не является доказательством, что человек прочитал объявление: offline-запрос может не дойти, блокировка/закрытие приложения может помешать отправке, а анонимную identity технически можно сменить. Сервер проверяет действительность точки/баннера и ограничивает повторы, но не может независимо доказать видимость экрана. До применения миграции `20261009150000_add_partner_statistics` на целевой БД endpoint записи не следует включать в рабочий mobile/backend релиз.

Отчёт не показывает «уникальных посетителей»: дневные агрегаты не позволяют честно посчитать их за 7/30 дней или всё время, а короткоживущие окна дедупликации для этого не предназначены. Для общей сводки 7/30 дней добавлен индекс по дню и действию; подсчёт за всё время идёт по дневным агрегатам, не по сырым кликам. Общие количества дорожных меток по источнику и партнёрских точек кэшируются в процессе backend на 60 секунд, чтобы не пересчитывать их при каждом открытии меню; поэтому они могут отставать до минуты. Скорость на реальном объёме рабочей БД до выката не измерялась.
