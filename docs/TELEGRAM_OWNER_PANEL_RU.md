# Панель владельца OnMap в Telegram

Панель использует **существующий единственный** Bot API long-polling consumer. Второй `getUpdates` не создаётся. Доступ к каждому экрану и callback проверяется по `TELEGRAM_PARTNER_OWNER_IDS` или, для модерации, `TELEGRAM_MODERATION_CHAT_ID`, только в личном чате владельца. Callback содержит короткий непрозрачный токен, а экран и действия хранятся в PostgreSQL. Старые кнопки после перехода/действия требуют обновления.

## Вход и основные действия

- `/start` или `/menu` открывает главное меню. `/help` показывает помощь; `/cancel` отменяет текущий партнёрский или push-мастер. Старые команды сохраняются для совместимости, но основной путь — кнопки.
- **Партнёрские точки → Создать точку**: выбрать город, затем отвечать на вопросы мастера. Точку можно указать геопозицией Telegram или координатами. На предпросмотре можно изменить отдельное поле, сохранить незавершённый черновик или подтвердить публикацию. Черновик живёт 24 часа с последнего действия; публикации до подтверждения нет. В списке доступны фильтры, пагинация, редактирование, изображение, контакты, промокод, пауза, возобновление и завершение с подтверждением.
- **Баннеры → город**: отдельно доступны предпросмотр, быстрые кнопки изменения заголовка/текста, действия и срока, включение с подтверждением, пауза и завершение. Изменение выключенного баннера не включает его автоматически. Новый баннер проходит мастер с выбором активной точки и предпросмотром. Пауза сохраняет срок, завершение выключает баннер и заканчивает срок; точка при этом не изменяется. Статистика баннера включена в статистику связанной точки.
- **Push-рассылки**: информационная начинается в разделе push, партнёрская — из карточки активной точки. Мастер собирает аудиторию, заголовок, текст и расписание `Europe/Saratov`, показывает предпросмотр и оценку аудитории. Создание/активация происходит только по кнопке подтверждения. Из списка кампаний доступны детали, статистика за 7/30 дней и всё время, редактирование, пауза, возобновление, завершение с подтверждением. «Отправить тест мне» не запускает общую кампанию.
- **Модерация**: открытые и решённые дела, активные ограничения без показа identity, поиск дела по ID и кнопки решения. «Закрыть без действия» записывает аудит, не ограничивает автора и оставляет уже скрытую метку скрытой до исходного истечения. Восстановление истёкшей метки запрещено существующей backend-проверкой.
- **Статистика**: общая сводка и детали точки/кампании с периодами 7/30 дней и всё время. Принятие APNs/FCM не означает фактический показ на телефоне.

## Адресный тест на телефоне владельца

Telegram ID владельца не угадывается из анонимной mobile identity. Без новой мобильной сборки владелец может в **Настройках** нажать **Прислать код на единственный iPhone**: backend допускает этот путь только при ровно одном активном APNs-устройстве с включёнными предложениями. Код приходит в адресном push; владелец отправляет его в личный чат бота в течение 10 минут. Только знание кода доказывает владение устройством. Повторы и ошибки ограничены, код хранится в БД только как hash; новая успешная привязка заменяет прежнюю цель. Принятие APNs не гарантирует показа уведомления на экране. Этот вызов не ставит ничего в массовый outbox.

Есть и резервный вариант: бот выдаёт код, который вводится в приложении через колокольчик → **Привязать для теста**. Для него нужен новый mobile build. После привязки адресный тест разрешён лишь при одной привязанной активной цели с включёнными предложениями; отправка идёт напрямую к провайдеру, минуя общий outbox, не чаще раза в минуту. Токен не выводится в бот и логи.

Новый mobile build **не требуется для привязки через APNs-код**, если есть ровно один подходящий iPhone. До подтверждения кода кнопку теста нельзя считать настроенной. Кнопка не является доказательством фактического получения push: это подтверждается на телефоне.

## Деплой и проверка

Новая миграция `20261014100000_telegram_bot_panel` создаёт таблицы сессий панели, непрозрачных действий и привязки тестового устройства. Для реального VPS: сначала backup с restore-проверкой, затем миграция, сборка и пересоздание **только одного** backend-контейнера. Нельзя сбрасывать Telegram cursor, создавать второго poller, переигрывать историю или отправлять массовые push во время smoke. После старта проверить `/api/health`, REST, оба advisory lock и восстановление Bot API/MTProto. В личном чате проверить `/start`, переходы и возврат, открыть списки/статистику/push-мастер; создать и отменить только тестовый незавершённый черновик, не публикуя точку и не подтверждая рассылку.

Локальная интеграционная проверка запускается только на отдельной БД с именем `onmap_it...` на `127.0.0.1`, после применения миграций: `NODE_OPTIONS=--experimental-vm-modules PANEL_INTEGRATION_DISPOSABLE=1 PANEL_INTEGRATION_DATABASE_URL=<адрес_одноразовой_БД> npx jest --config test/jest-owner-panel-integration.json --runInBand` из `backend/`. Тестовый push использует mock-провайдера, не Telegram/APNs.
