# OnMap: первый этап разрешений на уведомления

Этот этап не регистрирует push-токен и не отправляет уведомления. Разрешение само по себе не означает, что уведомления уже работают.

## Интерфейсный контракт

- `checkNotificationPermission()` возвращает `granted`, `limited`, `notDetermined`, `denied` или `unavailable`. Состояние сверяется с ОС при открытии карты и после возвращения из настроек.
- `requestNotificationPermissionOnce()` вызывается после объяснения на последнем экране первого запуска: сначала завершается запрос геолокации, затем открывается системный запрос уведомлений. Факт попытки сохраняется локально до системного диалога; при следующем запуске повторного запроса нет.
- Колокольчик на карте объясняет ещё не запрошенное разрешение, после отказа ведёт в настройки уведомлений. Карта и ручной выбор точки доступны при любом ответе.
- Для `limited` доступ не считается отказом. При системной ошибке показывается безопасный путь в настройки; ошибка не блокирует вход.

## Следующий этап

Отдельно понадобятся регистрация push-токена, безопасная привязка к установке/identity, отзыв токена, серверные правила типов событий и партнёрских предложений, доставка через APNs/FCM и проверка согласия перед отправкой. Ни один из этих механизмов не реализован здесь.
